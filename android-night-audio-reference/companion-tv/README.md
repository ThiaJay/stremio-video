# Native Fire TV companion MVP (source and device gate)

This is a **separately packaged Android TV proof application**, `org.thiajay.stremiotvcompanion`, staged alongside the already accepted Night Audio Android Media3 reference. It does not replace or alter `com.stremio.one`. It is **not** the official Stremio Android TV client, a deployed app, a production account client, or proof of physical Fire TV usability. No Stremio credentials, source links, account data or remote debugging operations are included.

## Currently implemented

* An Android TV Leanback launcher activity with actual `Media3 ExoPlayer`, native TV focusable buttons, real seek commands and lifecycle release on stop/destroy. The source now also supplies a unique 320dp × 180dp, neutral Companion Lab launcher vector banner required by Android TV. It is not the official Stremio artwork.
* A deterministic **offline 12-second PCM WAV** sample, generated only on the device after explicit activation. The intro, recap and credits ranges in this mode are **synthetic fixtures only**. They do not claim to identify timings in any actual television programme.
* The original 53-assertion offline bridge regression remains mandatory. `NativeTvBridge.kt` now carries one narrow watched-contract correction: a valid Story Order may still contain Season 0 presentation entries, but series-level watched plans filter every Season 0 item before creating a Core command. The accepted corrected source is pinned at SHA-256 `789e29b997b503ee6cac03d638a7da023ecef551c866fbafe36287ce36862715`; additional host Core-dispatch and source-switching tests remain in place.
* `SnapshotBoundNativeSeekPort` now supplies a **one-use, final player-state lease** to close the gap between Core dismissal and the actual Media3 seek. It rechecks generation, canonical video identity, readiness, duration, native transition flags, Next Episode popup and whether playback already passed the intended target immediately before seeking. It must run on the host-owned single player/Looper thread; it is not an atomic cross-device account transaction. Regression tests deliberately switch the selected video after Core acceptance and verify that Media3 does not seek the wrong episode.
* `NativeTvSkipActuator` is an injection boundary which dispatches the existing Core `Player.DismissSkipSegment` **before** issuing a same-video native Media3 seek. A changed generation, selected video, duration, buffering, next-episode popup or Core refusal blocks seeking. Its source contains no direct `NextVideo` or watched-state mutation.
* `NativeTvWatchedActuator` prepares whole-series and season watched actions only after a real account-side `StremioAccountPort` supplies fresh Core metadata and account record, then reconfirms before dispatch. `NativeTvEpisodeWatchedActuator` now also prepares individual canonical episode watched and unwatched from the **original fully loaded Core Video** using `MetaDetails.MarkVideoAsWatched([Video, bool])`, rejecting future episodes, changed video objects, account drift and repeated remote activation. The single-episode adapter now also checks the **entire canonical nested Video payload twice** and dispatches only a **deeply detached** copy, never a mutable Core-owned map, eliminating a stale-same-ID metadata race. Nonfinite numeric metadata fails closed. Neither source is reconstructed from the on-screen story order. The **actual app does not supply an authenticated account port**. Its watched controls are disabled, rather than silently fabricating watched history.
* `NativeTvTitleWatchedMenu` now provides the Android TV presentation boundary for whole-series and season watched/unwatched actions. It builds at most four focusable actions from one fresh canonical Core account snapshot, exposes no mutation while enumerating, accepts only the exact menu-issued object with matching focus and ENTER/DPAD_CENTER, requires explicit acknowledgement for unwatched operations, consumes the complete rendered generation before a fresh confirmation read and dispatch so no sibling action can survive one activation attempt, and is confined to one owner thread with permanent close. An accepted dispatch is now reported as `DISPATCHED_PENDING_READBACK` unless a `CanonicalWatchedStatePort` immediately proves the intended stable IDs against the same current account, library item and series. The returned watched-ID collection is detached inside the exception boundary before validation, so a mutable or throwing Core wrapper fails closed instead of escaping into the UI thread. Until that canonical watched bitmap matches, every later presentation is empty; malformed, duplicate, out-of-catalogue or mismatched readback never reopens the action generation. Future or unknown season entries suppress unsafe season actions. The disclosed side-by-side TV lab now wires it only through the accepted Android TV screen owner to a local in-memory synthetic account host. This proves isolated UI composition, not adoption by the private Android clients, authenticated account behavior or Fire TV device acceptance.
* `NativeMobileTitleWatchedMenu` projects those same guarded Core plans into an Android mobile presentation boundary without adding another account-write path. It accepts only the exact issued mobile action, the selected action ID and the framework-level semantic `ACTIVATE` event used by click, keyboard and accessibility activation. Raw pointer and long-press events are not consent. The complete mobile generation is consumed before the existing TV/Core delegate re-reads and dispatches, so a sibling action cannot execute after one selection. It is also deliberately unwired, so this is shared Kotlin source validation rather than private-client UI adoption or mobile device acceptance.
* `NativeMobileTitleWatchedHostBinding` adds the next real-host injection boundary without wiring the synthetic Activity. A narrow display-only view port receives immutable action models and cannot dispatch Core messages. Semantic callbacks must return the exact issued object and selected ID; every attempt revokes the whole rendered generation. Stale or forged objects, pointer/long-press events, account drift, rejected/throwing UI ports, wrong-thread use, post-close callbacks and accepted writes without canonical watched-state readback fail closed. Core confirmation and dispatch remain exclusively in the existing mobile -> TV -> canonical Core coordinator path.
* `NativeTvTitleWatchedHostBinding` supplies the corresponding focusable Android TV host boundary. Its display-only port receives immutable models with explicit acknowledgement metadata. ENTER and DPAD_CENTER callbacks must return the exact issued object and focused ID. Every attempt revokes the full generation; focus/key mismatch, stale or forged objects, account drift, UI replacement/clear failure, wrong-thread use, post-close callbacks and accepted writes without canonical watched-state readback fail closed. It remains unwired from the synthetic Activity and delegates all confirmation and Core dispatch to `NativeTvTitleWatchedMenu`.
* `AndroidTvTitleWatchedWidgetPort` is the first actual Android widget implementation of that view port. It creates only focusable `Button` views on the main owner thread, captures the exact issued action object, accepts remote ENTER/DPAD_CENTER key-up with real focus, removes its complete owned view generation before callback, and presents a positive/cancel confirmation dialog for destructive unwatched actions. Each destructive dialog now holds an exact one-use controller lease. Replacement, clear and close revoke the lease and dismiss the owned dialog; a delayed callback from an older dialog cannot resolve or revoke a newer confirmation. `NativeTvTitleWatchedWidgetController` independently rejects malformed generations, reconstructed widgets, stale focus, wrong keys, replay, forged confirmation leases, foreign threads and post-close use. The adapter has no Core, credential or network access. The disclosed side-by-side TV lab now instantiates it only through the accepted screen owner against local in-memory synthetic state, so private-client adoption and device acceptance remain open.
* `AndroidMobileTitleWatchedWidgetPort` supplies the matching actual Android mobile `Button` implementation. Framework click, accessibility click and keyboard activation share the single semantic `ACTIVATE` path; raw touch coordinates are never accepted and long-press is consumed without activation. The exact action object and selected ID survive the widget controller, all owned views are removed before callback, and destructive unwatched operations require an explicit positive confirmation while cancel or dismissal returns a refusal. Destructive confirmation is now bound to one exact controller-issued lease; replacement, clear and close revoke that lease and dismiss the old dialog without allowing a delayed stale callback to interfere with a newer generation. The adapter is main-thread confined, has no Core, credential or network surface and remains deliberately uninstantiated by the synthetic Activity.
* `NativeMobileTitleWatchedViewPortRelay` and `NativeTvTitleWatchedViewPortRelay` close the safe-construction gap between a host binding and its later real Android view. Each relay is owner-thread confined, binds exactly once, permanently poisons on rebind, delegate refusal or exception, and revokes its delegate on close. `AndroidMobileTitleWatchedScreenOwner` and `AndroidTvTitleWatchedScreenOwner` are actual main-thread composition roots for the accepted host and widget ports. Each holds one activation outcome until the client explicitly consumes it, blocking silent re-render over an unobserved result. A fatal host or view failure is distinguished from a recoverable canonical-readback wait: fatal closure revokes the screen-owned account adapter immediately while preserving the already produced outcome for one final owner-thread consumption. Their constructors and every underlying mobile/TV menu and host-binding constructor now require `CanonicalWatchedStatePort` at compile time, so no title-action UI layer can be composed through the weaker dispatch-only account interface. The TV owner is now present only in the disclosed synthetic TV launcher, while the mobile owner remains in the separate disclosed synthetic mobile launcher. Neither provides an authenticated account implementation or private-client adoption.
* `SessionBoundCanonicalWatchedAccountAdapter` supplies the concrete narrow private-client handoff for those UI owners without adding credentials or a general Core command surface. It detaches canonical episode, Story Order and watched-ID collections between equal session-epoch reads; binds readback to the complete snapshot last returned to the menu; accepts only exact series/season watched commands; consumes its snapshot lease before every dispatch precondition; and verifies the epoch after the host call. A failed snapshot refresh, mismatched watched-state readback or failed dispatch precondition invalidates the prior identity lease, so returning to an earlier epoch and snapshot cannot revive stale authority. All account operations remain owner-thread confined. Permanent close is a synchronised cross-thread revocation boundary: it waits for an in-flight owner operation and prevents every later host callback, allowing asynchronous host teardown without transferring account access to another thread. The mobile and TV screen owners also expose typed host-port factories that create and own this adapter. Their shared construction boundary revokes the owned adapter when construction returns no screen or throws an ordinary exception or linkage failure, while successful construction transfers the still-live adapter to the screen owner. Each screen retains an idempotent owned-account lease with a sticky termination request. Foreign host teardown or a foreign-thread UI callback records termination and revokes only the internally created adapter; neither path touches Android view, relay or menu objects. The next main-owner-thread render, outcome read or callback performs the remaining UI cleanup and refuses stale use. Externally supplied canonical ports remain caller-owned and the no-adapter lease only records screen termination. Poison and ordinary screen closure also revoke only the owned adapter. The factories remain absent from the synthetic Activity and therefore are implementation guidance, not authenticated client or device acceptance.
* `NativeSubtitlePreferenceProvenance` is a pure, unwired Kotlin translation of Foundation PR #70's exact installation-local subtitle-preference provenance contract at head `99ea3173184029bbd7ee5ae7dc33d31d553fc135` and runtime blob `e63e9a35ec9e0bdeab0de17debaf5a3ce929d8d4`. It rejects malformed or cross-installation receipts, binding drift, unreviewed choice surfaces, inferred consent from an enabled flag/account hydration/preferred language, and promotion without exact installation-local storage readback. Caller-owned receipt, binding, choice-event and storage-readback maps are now copied once through a bounded exact-cardinality iterator snapshot; throwing, changing, oversized or nested-hostile maps fail closed without escaping or being reread. Explicit Off remains authoritative. The boundary has no storage, account, player, network or UI access and is deliberately absent from both synthetic Activities, so it is source validation only—not proof of a real first-run/settings choice, private-client adoption, persistence, package identity or device acceptance.
* `NativeSubtitlePreferenceReceiptCodec` is the deterministic, versioned and bounded native representation for an exact explicit-choice receipt; malformed Base64, non-canonical encodings, invalid UTF-8, oversized text, schema drift and trailing bytes fail closed. `NativeSubtitlePreferenceStore` remains the deliberately unwired native installation-local persistence handoff. It accepts only an injected typed two-slot port whose digest and canonical encoded-receipt mutations are exact-string atomic compare-and-set operations, requires stable double readback before and after a write, increments only a validated prior explicit-choice revision, promotes through the accepted provenance verifier and uses compare-and-set rollback only while both slots still contain the original or transaction-owned values. Unknown concurrent drift is preserved and reported as unverified rollback. Explicit Off clears only the receipt and retains the installation identity. The store is owner-thread confined, has no `SharedPreferences`, DataStore, Android context, account, player, network or UI access and is absent from both synthetic Activities. It is a source contract for a future private-client host—not evidence of actual persistence, a genuine UI choice, client adoption or device acceptance.
* `SecureRandomSubtitlePreferenceDigestSource` supplies the bounded opaque installation identity needed by the native store without deriving it from an account, package, device identifier, locale or preference. It requires 32 fresh non-zero entropy bytes, emits exactly 64 lowercase hexadecimal characters, contains runtime and linkage failures, clears the raw entropy buffer and is owner-thread/close confined. The default implementation uses `SecureRandom`; deterministic entropy is injectable only for isolated tests. It is absent from both synthetic Activities and has no storage, Android `Context`, account, network, player or UI access, so it does not establish lifecycle wiring or production identity persistence.
* `AndroidSubtitlePreferenceSharedPreferencesPort` is the concrete, owner-thread Android implementation of that two-slot port. It accepts only an injected `SharedPreferences` object, owns two fixed private keys, serialises adapter instances sharing that exact object, uses synchronous `commit()` and requires exact post-commit readback. Wrong types, read/edit/commit exceptions, compare mismatch, failed commit and changed readback fail closed; explicit removal touches only the selected slot. Its atomicity is deliberately process-local and depends on exclusive ownership of those keys. It has no `Context`, account, network, player or UI access and remains absent from both synthetic Activities, so it is source validation—not private-client wiring, cross-process safety, persistence acceptance or device acceptance.
* `AndroidSubtitlePreferenceStoreOwner` is the unwired process-local composition root for those three accepted pieces. It leases the exact injected `SharedPreferences` object to one live owner, binds the two-slot adapter, opaque identity source and canonical store, forwards only the validated load/explicit-choice/explicit-Off operations and closes every component before releasing the lease. A second owner for the same object, foreign-thread use, ambiguous close or corrupt storage fails closed. The lease is identity-based and process-local, not a cross-process lock; the caller still owns the private preferences object and proof of a genuine first-run or subtitle-settings event. The owner has no `Context`, account, network, player or UI access and remains absent from both synthetic Activities.
* `AndroidSubtitlePreferenceChoiceSession` adds an unwired one-shot handoff in front of that owner. A reviewed typed first-run or subtitle-settings surface must prepare exactly one enabled/Off choice against a stable double-read preference snapshot; only the same instance-issued lease can return, and it is consumed before the complete snapshot is re-read and before storage is touched. Cross-session, forged, duplicate, stale, cancelled, wrong-thread and post-close callbacks fail closed. The underlying store mutations are module-internal. This object provenance still cannot prove a genuine Android view callback, so the class remains absent from both synthetic Activities and is not private-client UI, accessibility, persistence or device acceptance.
* `AndroidSubtitlePreferenceChoiceWidgetController` and `AndroidSubtitlePreferenceChoiceWidgetPort` add the actual, still-unwired Android semantic callback boundary in front of that session. The controller issues exactly two immutable enabled/Off widgets for one reviewed first-run or subtitle-settings surface; only the exact widget object, matching selected choice and semantic `ACTIVATE` callback can produce an intent, and every attempt revokes the complete generation. The Android adapter creates focusable `Button` views on the main owner thread, routes framework click, keyboard and accessibility activation through `performClick`, consumes long-press without consent, accepts no raw touch coordinates, removes every owned view before preparing the exact one-shot session lease and returns the typed commit result to its host. Replacement, clear, failure and close revoke UI and storage authority. The adapter remains absent from both lab Activities and has no account, network, player or provider surface, so this is source/software proof of the callback boundary—not evidence of a private-client first-run/settings screen, authenticated behavior, persistence, signed delivery or device acceptance.
* `AndroidSubtitlePreferenceChoiceScreenOwner` supplies the still-unwired lifecycle and outcome boundary above that widget port. It holds exactly one typed success or refusal until the client explicitly consumes it, blocks rendering or clearing over an unobserved result, and permanently revokes the port on duplicate delivery, render/clear refusal, exception, wrong-thread use or close. Production construction requires the Android main Looper and composes the accepted `SharedPreferences`, snapshot, client-owned preference-application and widget path. The owner is absent from both lab Activities and has no account, player, provider or network access, so it does not establish a genuine private-client screen, persistence-key ownership, authenticated behavior or device acceptance.
* `AndroidSubtitlePreferenceChoiceTransaction` closes the semantic gap between those enabled/Off buttons and the private client's existing local preference authority without implementing a second preference store. Its injected port must return an exact before/after transition that changes only the enabled value and preserves language, source and global-language binding. Receipt storage follows stable preference readback; admission failure rolls back only while the current preference still equals the transaction-owned after snapshot, while concurrent drift is preserved and reported as unverified rollback. Exceptions, forged transitions, wrong-thread use and close fail closed. The widget and screen owner now require this port, but no implementation is supplied and the complete path remains absent from both lab Activities. This is source validation of an integration transaction—not private-client adoption, production preference mutation, signed delivery or device acceptance.
* A pure Kotlin Story Order presentation adapter now validates version 1 hints, rejects duplicate, unknown or incomplete regular-episode sequences, returns the original canonical episode objects and supplies a stable-ID Next Story override candidate without bypassing existing player gates. A focusable TV control demonstrates canonical versus Story Order presentation using only synthetic local metadata, including one narrative Season 0 entry and one omitted ancillary extra. It has no catalogue, player, account or watched-state binding and is not native-client or device acceptance.
* A numeric-only Media3 failure intake now maps the Android player's stable error code into the sanitised PR #75 facts contract. It never accepts exception messages, causes, URLs, headers, credentials or account state; it does not guess an HTTP status from Media3's generic HTTP error and never self-authorises playback-health recovery. The current local fixture listener exposes only the resulting category and performs no retry, source change or recovery actuation.
* `NativeMedia3RetryActuator` adds a separate source-only handoff for the classifier-owned transport retry. A mandatory `NativeMedia3RetryBudget` is created for one episode-session and canonical video, retained by the host across actuator or player-adapter replacement, and has no reset operation. It is the sole same-episode attempt counter: the host snapshot cannot declare or reset retry history. Preparation reserves that shared budget before returning a lease, so replacement, abandoned leases, source/load-generation changes and rejected calls cannot mint another attempt. The exact snapshot is re-read and the token is consumed before the injected port call. Episode advance, a user-requested next episode, released or transitioning player state, terminal/unknown Media3 codes, snapshot drift, cross-instance replay, budget close and adapter failures all fail closed. The local fixture intentionally does not instantiate either boundary; no real retry, source switch, stream, provider, account or device operation is wired.
* A native Kotlin classification-first recovery planner now implements the strict Foundation PR #75 to PR #77 boundary. Provider, source and transport retries exclusively own their one classifier attempt; Matroska, container, decoder, DRM, EGL, backend-loop, episode and unclassified stops cannot fall through to playback recovery. Only the exact version-1 playback-health delegation with matching immutable video/source/load context and an explicit bounded attempt ledger can select an existing recovery action. The planner performs no actuation, network, account or provider operation.
* `NativePlaybackRecoveryActuator` now supplies a source-only one-shot handoff for an accepted playback-health plan. It leases the exact context, video, source, load generation, watched-state fingerprint, resume-state fingerprint and the port's explicitly reviewed recovery capabilities; rejects a planned action the port did not advertise; registers the lease to the producing actuator instance; refuses duplicate preparation, cross-instance replay and any prepare or execute call outside the construction thread; then re-reads the complete snapshot immediately before the injected port call and consumes the lease before execution. An explicit owner-thread close permanently revokes outstanding leases and clears retained issuance state when the host player is released. Snapshot and action adapter exceptions or linkage failures are contained and converted to fail-closed outcomes; an action failure still consumes its one-shot lease. Lease registration is capped at 256 unique entries per actuator lifetime; reaching the cap fails closed without evicting older tokens or reopening replay. Terminal and classifier-owned retries can never prepare an actuator call. No concrete Media3 recovery, source operation, account write or device binding is included.
* Night Audio Off/Gentle/Balanced/Strong buttons reuse the already implemented `NightAudioMedia3Processor` and PCM processor. It is **Off by default**. The panel says that processing was observed only when actual PCM frames were processed, not when a button was merely selected. Audible quality and soundbar identification remain unverified.
* Separate package identity, no Android network/storage/account/overlay/boot/accessibility permissions, `allowBackup=false`, `usesCleartextTraffic=false` and no exported activity except the launcher. No external video URL ingestion in this build. No user data persistence except the locally generated throwaway WAV in app cache.

## Build/test

Use the existing Gradle 8.11.1 and Android SDK 35/36 setup for `android-night-audio-reference`:

```sh
gradle -p android-night-audio-reference :processor:testDebugUnitTest :companion-tv:compileDebugKotlin :companion-tv:testDebugUnitTest :companion-tv:assembleDebug
```

Source-only offline tests on a machine with JDK 21 and Kotlin compiler 1.9+:

```sh
kotlinc android-night-audio-reference/companion-tv/src/main/java/org/pss/stremio/tv/NativeTvBridge.kt \
  android-night-audio-reference/companion-tv/src/main/java/org/pss/stremio/tv/NativeTvPorts.kt \
  android-night-audio-reference/companion-tv/src/test/java/org/pss/stremio/tv/BridgeSmokeTest.kt \
  -include-runtime -d /tmp/native-tv-companion-bridge.jar
java -jar /tmp/native-tv-companion-bridge.jar
```

CI must run the native SDK compilation, test and manifest audit on the **exact candidate head**, preserve the APK's SHA-256 and avoid any release/upload/install. Passing Kotlin JVM tests alone is insufficient for a functioning Android APK.

## Missing before production integration

1. A licenced, maintained Stremio Core native account/session client and proper addon/stream selection, with no reuse of private credentials. The existing `stremio-core-kotlin` runtime requires independent architecture, SDK, dependency, privacy and trust review before adoption. Neither NuvioTV nor an unrelated external player provides proven Stremio account parity.
2. Real provider-neutral resolved skip evidence with exact canonical episode/stream identity. Synthetic time windows must **never** be applied to actual programmes. Core skip message acknowledgement and Media3 seek must be wired to the actual player.
3. Fresh Core watched bitmap and authorised private-client binding for the source-validated episode, series and season actions, followed by isolated account acceptance. Both Android mobile and Android TV now expose their real widget adapters and explicit screen composition owners only in disclosed side-by-side lab launchers backed by local in-memory synthetic state. Private clients must still supply their authenticated Core port, adopt the lifecycle boundary and pass account and device acceptance. Story Order still needs authorised real Core metadata binding, player/Continue Watching integration and remote/device acceptance. Do not infer completion from source-only actions. Subtitle-preference provenance additionally requires the private Android clients to instantiate the source-validated opaque random installation identity, semantic choice widget port and one-outcome screen owner inside a reviewed lifecycle, supply an exclusive private `SharedPreferences` instance, bind the owner to a genuine first-run or subtitle-settings screen, consume and reconcile the typed result, perform exact post-write readback and pass privacy/accessibility review; the unwired source components are not private-client persistence or device acceptance, and an enabled flag, account hydration or language value is never consent.
4. Playback of authorised real video/audio streams, DRM/format support, subtitles, remote accessibility, resume and crash recovery with test account and verified before/after state. The native classification-first planner and one-shot actuator boundary still require a reviewed source-bound classifier input, a real host snapshot implementation and individually reviewed native action bindings before any recovery can affect playback. Real TV ADB is not currently connected; don't loop reconnection attempts.
5. Full Night Audio routing and listener/physical acoustic acceptance and more codec cases. No processing state is advertised as hardware-accepted.
6. Exact-source supply chain, dependency security, licence, rollback and user-approved installation acceptance. The working official Stremio 1.11.2 and account stay untouched.

**Install gate:** never install or distribute this MVP as a final Stremio client. It is a development candidate. Its source, tests and expected APK identity are preserved for independent review and later approved device tests.
