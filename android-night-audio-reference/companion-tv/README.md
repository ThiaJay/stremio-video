# Native Fire TV companion MVP (source and device gate)

This is a **separately packaged Android TV proof application**, `org.thiajay.stremiotvcompanion`, staged alongside the already accepted Night Audio Android Media3 reference. It does not replace or alter `com.stremio.one`. It is **not** the official Stremio Android TV client, a deployed app, a production account client, or proof of physical Fire TV usability. No Stremio credentials, source links, account data or remote debugging operations are included.

## Currently implemented

* An Android TV Leanback launcher activity with actual `Media3 ExoPlayer`, native TV focusable buttons, real seek commands and lifecycle release on stop/destroy. The source now also supplies a unique 320dp × 180dp, neutral Companion Lab launcher vector banner required by Android TV. It is not the official Stremio artwork.
* A deterministic **offline 12-second PCM WAV** sample, generated only on the device after explicit activation. The intro, recap and credits ranges in this mode are **synthetic fixtures only**. They do not claim to identify timings in any actual television programme.
* The exact previous `NativeTvBridge.kt` is reused without editing (SHA-256 `0e067446053abc456196d060bc96dff72d03902542fb9ae97cefd47fa143f23b`). The original 53-assertion offline regression is retained and executed as a JVM test, plus additional host Core-dispatch and source-switching tests.
* `SnapshotBoundNativeSeekPort` now supplies a **one-use, final player-state lease** to close the gap between Core dismissal and the actual Media3 seek. It rechecks generation, canonical video identity, readiness, duration, native transition flags, Next Episode popup and whether playback already passed the intended target immediately before seeking. It must run on the host-owned single player/Looper thread; it is not an atomic cross-device account transaction. Regression tests deliberately switch the selected video after Core acceptance and verify that Media3 does not seek the wrong episode.
* `NativeTvSkipActuator` is an injection boundary which dispatches the existing Core `Player.DismissSkipSegment` **before** issuing a same-video native Media3 seek. A changed generation, selected video, duration, buffering, next-episode popup or Core refusal blocks seeking. Its source contains no direct `NextVideo` or watched-state mutation.
* `NativeTvWatchedActuator` prepares whole-series and season watched actions only after a real account-side `StremioAccountPort` supplies fresh Core metadata and account record, then reconfirms before dispatch. `NativeTvEpisodeWatchedActuator` now also prepares individual canonical episode watched and unwatched from the **original fully loaded Core Video** using `MetaDetails.MarkVideoAsWatched([Video, bool])`, rejecting future episodes, changed video objects, account drift and repeated remote activation. The single-episode adapter now also checks the **entire canonical nested Video payload twice** and dispatches only a **deeply detached** copy, never a mutable Core-owned map, eliminating a stale-same-ID metadata race. Nonfinite numeric metadata fails closed. Neither source is reconstructed from the on-screen story order. The **actual app does not supply an authenticated account port**. Its watched controls are disabled, rather than silently fabricating watched history.
* `NativeTvTitleWatchedMenu` now provides the Android TV presentation boundary for whole-series and season watched/unwatched actions. It builds at most four focusable actions from one fresh canonical Core account snapshot, exposes no mutation while enumerating, accepts only the exact menu-issued object with matching focus and ENTER/DPAD_CENTER, requires explicit acknowledgement for unwatched operations, consumes issuance before a fresh confirmation read and dispatch, and is confined to one owner thread with permanent close. An accepted dispatch is now reported as `DISPATCHED_PENDING_READBACK` unless a `CanonicalWatchedStatePort` immediately proves the intended stable IDs against the same current account, library item and series. The returned watched-ID collection is detached inside the exception boundary before validation, so a mutable or throwing Core wrapper fails closed instead of escaping into the UI thread. Until that canonical watched bitmap matches, every later presentation is empty; malformed, duplicate or mismatched readback never reopens the action generation. Future or unknown season entries suppress unsafe season actions. It is intentionally **not wired to the synthetic Activity** and therefore proves source behavior only, not adoption by the private Android clients or Fire TV device acceptance.
* `NativeMobileTitleWatchedMenu` projects those same guarded Core plans into an Android mobile presentation boundary without adding another account-write path. It accepts only the exact issued mobile action, the selected action ID and the framework-level semantic `ACTIVATE` event used by click, keyboard and accessibility activation. Raw pointer and long-press events are not consent. Issuance is consumed before the existing TV/Core delegate re-reads and dispatches. It is also deliberately unwired, so this is shared Kotlin source validation rather than private-client UI adoption or mobile device acceptance.
* `NativeMobileTitleWatchedHostBinding` adds the next real-host injection boundary without wiring the synthetic Activity. A narrow display-only view port receives immutable action models and cannot dispatch Core messages. Semantic callbacks must return the exact issued object and selected ID; every attempt revokes the whole rendered generation. Stale or forged objects, pointer/long-press events, account drift, rejected/throwing UI ports, wrong-thread use, post-close callbacks and accepted writes without canonical watched-state readback fail closed. Core confirmation and dispatch remain exclusively in the existing mobile -> TV -> canonical Core coordinator path.
* `NativeTvTitleWatchedHostBinding` supplies the corresponding focusable Android TV host boundary. Its display-only port receives immutable models with explicit acknowledgement metadata. ENTER and DPAD_CENTER callbacks must return the exact issued object and focused ID. Every attempt revokes the full generation; focus/key mismatch, stale or forged objects, account drift, UI replacement/clear failure, wrong-thread use, post-close callbacks and accepted writes without canonical watched-state readback fail closed. It remains unwired from the synthetic Activity and delegates all confirmation and Core dispatch to `NativeTvTitleWatchedMenu`.
* `AndroidTvTitleWatchedWidgetPort` is the first actual Android widget implementation of that view port. It creates only focusable `Button` views on the main owner thread, captures the exact issued action object, accepts remote ENTER/DPAD_CENTER key-up with real focus, removes its complete owned view generation before callback, and presents a positive/cancel confirmation dialog for destructive unwatched actions. `NativeTvTitleWatchedWidgetController` independently rejects malformed generations, reconstructed widgets, stale focus, wrong keys, replay, foreign threads and post-close use. The adapter has no Core, credential or network access and is deliberately not instantiated by the synthetic Activity, so private-client adoption and device acceptance remain open.
* `AndroidMobileTitleWatchedWidgetPort` supplies the matching actual Android mobile `Button` implementation. Framework click, accessibility click and keyboard activation share the single semantic `ACTIVATE` path; raw touch coordinates are never accepted and long-press is consumed without activation. The exact action object and selected ID survive the widget controller, all owned views are removed before callback, and destructive unwatched operations require an explicit positive confirmation while cancel or dismissal returns a refusal. The adapter is main-thread confined, has no Core, credential or network surface and remains deliberately uninstantiated by the synthetic Activity.
* `NativeMobileTitleWatchedViewPortRelay` and `NativeTvTitleWatchedViewPortRelay` close the safe-construction gap between a host binding and its later real Android view. Each relay is owner-thread confined, binds exactly once, permanently poisons on rebind, delegate refusal or exception, and revokes its delegate on close. `AndroidMobileTitleWatchedScreenOwner` and `AndroidTvTitleWatchedScreenOwner` are actual main-thread composition roots for the accepted host and widget ports. Each holds one activation outcome until the client explicitly consumes it, blocking silent re-render over an unobserved result. Their constructors and every underlying mobile/TV menu and host-binding constructor now require `CanonicalWatchedStatePort` at compile time, so no title-action UI layer can be composed through the weaker dispatch-only account interface. They remain deliberately absent from the synthetic Activity and do not provide an authenticated account implementation.
* `SessionBoundCanonicalWatchedAccountAdapter` supplies the concrete narrow private-client handoff for those UI owners without adding credentials or a general Core command surface. It detaches canonical episode, Story Order and watched-ID collections between equal session-epoch reads; binds readback to the complete snapshot last returned to the menu; accepts only exact series/season watched commands; consumes its snapshot lease before dispatch; verifies the epoch after the host call; and is owner-thread confined with permanent close. The mobile and TV screen owners also expose typed host-port factories that create and own this adapter, close it on construction failure, poison or ordinary screen closure, and leave externally supplied canonical ports unowned. The factories remain absent from the synthetic Activity and therefore are implementation guidance, not authenticated client or device acceptance.
* A pure Kotlin Story Order presentation adapter now validates version 1 hints, rejects duplicate, unknown or incomplete regular-episode sequences, returns the original canonical episode objects and supplies a stable-ID Next Story override candidate without bypassing existing player gates. A focusable TV control demonstrates canonical versus Story Order presentation using only synthetic local metadata, including one narrative Season 0 entry and one omitted ancillary extra. It has no catalogue, player, account or watched-state binding and is not native-client or device acceptance.
* A numeric-only Media3 failure intake now maps the Android player's stable error code into the sanitised PR #75 facts contract. It never accepts exception messages, causes, URLs, headers, credentials or account state; it does not guess an HTTP status from Media3's generic HTTP error and never self-authorises playback-health recovery. The current local fixture listener exposes only the resulting category and performs no retry, source change or recovery actuation.
* `NativeMedia3RetryActuator` adds a separate source-only handoff for the classifier-owned transport retry. A mandatory `NativeMedia3RetryBudget` is created for one episode-session and canonical video, retained by the host across actuator or player-adapter replacement, and has no reset operation. It is the sole same-episode attempt counter: the host snapshot cannot declare or reset retry history. Preparation reserves that shared budget before returning a lease, so replacement, abandoned leases, source/load-generation changes and rejected calls cannot mint another attempt. The exact snapshot is re-read and the token is consumed before the injected port call. Episode advance, a user-requested next episode, released or transitioning player state, terminal/unknown Media3 codes, snapshot drift, cross-instance replay, budget close and adapter failures all fail closed. The local fixture intentionally does not instantiate either boundary; no real retry, source switch, stream, provider, account or device operation is wired.
* A native Kotlin classification-first recovery planner now implements the strict Foundation PR #75 to PR #77 boundary. Provider, source and transport retries exclusively own their one classifier attempt; Matroska, container, decoder, DRM, EGL, backend-loop, episode and unclassified stops cannot fall through to playback recovery. Only the exact version-1 playback-health delegation with matching immutable video/source/load context and an explicit bounded attempt ledger can select an existing recovery action. The planner performs no actuation, network, account or provider operation.
* `NativePlaybackRecoveryActuator` now supplies a source-only one-shot handoff for an accepted playback-health plan. It leases the exact context, video, source, load generation, watched-state fingerprint, resume-state fingerprint and the port's explicitly reviewed recovery capabilities; rejects a planned action the port did not advertise; registers the lease to the producing actuator instance; refuses duplicate preparation, cross-instance replay and any prepare or execute call outside the construction thread; then re-reads the complete snapshot immediately before the injected port call and consumes the lease before execution. An explicit owner-thread close permanently revokes outstanding leases and clears retained issuance state when the host player is released. Snapshot and action adapter exceptions or linkage failures are contained and converted to fail-closed outcomes; an action failure still consumes its one-shot lease. Lease registration is capped at 256 unique entries per actuator lifetime; reaching the cap fails closed without evicting older tokens or reopening replay. Terminal and classifier-owned retries can never prepare an actuator call. No concrete Media3 recovery, source operation, account write or device binding is included.
* Night Audio Off/Gentle/Balanced/Strong buttons reuse the already implemented `NightAudioMedia3Processor` and PCM processor. It is **Off by default**. The panel says that processing was observed only when actual PCM frames were processed, not when a button was merely selected. Audible quality and soundbar identification remain unverified.
* Separate package identity, no Android network/storage/account/overlay/boot/accessibility permissions, `allowBackup=false`, `usesCleartextTraffic=false` and no exported activity except the launcher. No external video URL ingestion in this build. No user data persistence except the locally generated throwaway WAV in app cache.

## Build/test

Use the existing Gradle 8.11.1 and Android SDK 35/36 setup for `android-night-audio-reference`:

```sh
gradle -p android-night-audio-reference :processor:testDebugUnitTest :companion-tv:compileDebugKotlin :companion-tv:testDebugUnitTest :companion-tv:assembleDebug
```

Source-only offline tests on a machine with JDK 21 and Kotlin compiler 1.9+:

```sh
kotlinc android-night-audio-reference/companion-tv/src/main/java/org/pss/stremio/tv/NativeTvBridge.kt \
  android-night-audio-reference/companion-tv/src/main/java/org/pss/stremio/tv/NativeTvPorts.kt \
  android-night-audio-reference/companion-tv/src/test/java/org/pss/stremio/tv/BridgeSmokeTest.kt \
  -include-runtime -d /tmp/native-tv-companion-bridge.jar
java -jar /tmp/native-tv-companion-bridge.jar
```

CI must run the native SDK compilation, test and manifest audit on the **exact candidate head**, preserve the APK's SHA-256 and avoid any release/upload/install. Passing Kotlin JVM tests alone is insufficient for a functioning Android APK.

## Missing before production integration

1. A licenced, maintained Stremio Core native account/session client and proper addon/stream selection, with no reuse of private credentials. The existing `stremio-core-kotlin` runtime requires independent architecture, SDK, dependency, privacy and trust review before adoption. Neither NuvioTV nor an unrelated external player provides proven Stremio account parity.
2. Real provider-neutral resolved skip evidence with exact canonical episode/stream identity. Synthetic time windows must **never** be applied to actual programmes. Core skip message acknowledgement and Media3 seek must be wired to the actual player.
3. Fresh Core watched bitmap and authorised private-client binding for the source-validated episode, series and season actions, followed by isolated account acceptance. Both Android mobile and Android TV now have host bindings, real widget adapters and explicit screen composition owners, all deliberately unwired from the synthetic Activity until the private clients supply their authenticated Core port and adopt the lifecycle boundary. Story Order still needs authorised real Core metadata binding, player/Continue Watching integration and remote/device acceptance. Do not infer completion from source-only actions.
4. Playback of authorised real video/audio streams, DRM/format support, subtitles, remote accessibility, resume and crash recovery with test account and verified before/after state. The native classification-first planner and one-shot actuator boundary still require a reviewed source-bound classifier input, a real host snapshot implementation and individually reviewed native action bindings before any recovery can affect playback. Real TV ADB is not currently connected; don't loop reconnection attempts.
5. Full Night Audio routing and listener/physical acoustic acceptance and more codec cases. No processing state is advertised as hardware-accepted.
6. Exact-source supply chain, dependency security, licence, rollback and user-approved installation acceptance. The working official Stremio 1.11.2 and account stay untouched.

**Install gate:** never install or distribute this MVP as a final Stremio client. It is a development candidate. Its source, tests and expected APK identity are preserved for independent review and later approved device tests.
