# Native Fire TV companion MVP (source and device gate)

This is a **separately packaged Android TV proof application**, `org.thiajay.stremiotvcompanion`, staged alongside the already accepted Night Audio Android Media3 reference. It does not replace or alter `com.stremio.one`. It is **not** the official Stremio Android TV client, a deployed app, a production account client, or proof of physical Fire TV usability. No Stremio credentials, source links, account data or remote debugging operations are included.

## Currently implemented

The source now also supplies a unique 320dp × 180dp, neutral Companion Lab launcher vector banner required by Android TV. It is not the official Stremio artwork.

## Build/test

Use the existing Gradle 8.11.1 and Android SDK 35/36 setup for `android-night-audio-reference`:

```sh
gradle -p android-night-audio-reference :processor:testDebugUnitTest :companion-tv:compileDebugKotlin :companion-tv:testDebugUnitTest :companion-tv:assembleDebug
```

Source-only offline tests on a machine with JDK 21 and Kotlin compiler 1.9+:

```sh
kotlinc android-night-audio-reference/companion-tv/src/main/java/org/pss/stremio/tv/NativeTvBridge.kt \
  android-night-audio-reference/companion-tv/src/main/java/org/pss/stremio/tv/NativeTvPorts.kt \
  android-night-audio-reference/companion-tv/src/test/java/org/pss/stremio/tv/BridgeSmokeTest.kt \
  -include-runtime -d /tmp/native-tv-companion-bridge.jar
java -jar /tmp/native-tv-companion-bridge.jar
```

CI must run the native SDK compilation, test and manifest audit on the **exact candidate head**, preserve the APK's SHA-256 and avoid any release/upload/install. Passing Kotlin JVM tests alone is insufficient for a functioning Android APK.

The exact-head workflow also creates a disposable Android 11/API 30 emulator and
runs `:companion-tv:connectedDebugAndroidTest`. Both explicit-Off and admitted
Enabled paths must execute the local Media3 fixture through the real subtitle
view draw and `PixelCopy` callback. No emulator result may be promoted to
physical-panel, Fire TV, official-client or hardware acceptance.

## Missing before production integration

1. A licenced, maintained Stremio Core native account/session client and proper addon/stream selection, with no reuse of private credentials. The existing `stremio-core-kotlin` runtime requires independent architecture, SDK, dependency, privacy and trust review before adoption. Neither NuvioTV nor an unrelated external player provides proven Stremio account parity.
2. Real provider-neutral resolved skip evidence with exact canonical episode/stream identity. Synthetic time windows must **never** be applied to actual programmes. Core skip message acknowledgement and Media3 seek must be wired to the actual player.
3. Fresh Core watched bitmap and authorised private-client binding for the source-validated episode, series and season actions, followed by isolated account acceptance. Both Android mobile and Android TV expose their title-action widget adapters and screen owners only in disclosed side-by-side lab launchers backed by synthetic state. Story Order still needs authorised real Core metadata binding, player/Continue Watching integration and remote/device acceptance. Subtitle provenance is composed only in the synthetic mobile and Android TV labs, with separate app-private preference and receipt namespaces surviving a fresh owner. The transition/recovery actuator is now bound only to the TV lab's synthetic local Media3 player. Private Android clients must still adopt the complete lifecycle with their existing preference authority, exclusive private keys, migration/update policy, exact post-write readback, real subtitle tracks and player transitions, and privacy/accessibility review. An enabled flag, account hydration or language value is never consent, and lab persistence or actuator tests are not client adoption or device acceptance.
4. Playback of authorised real video/audio streams, DRM/format support, subtitles, remote accessibility, resume and crash recovery with test account and verified before/after state. The native classification-first planner and one-shot actuator boundary still require a reviewed source-bound classifier input, a real host snapshot implementation and individually reviewed native action bindings before any recovery can affect playback. Real TV ADB is not currently connected; don't loop reconnection attempts.
5. Full Night Audio routing and listener/physical acoustic acceptance and more codec cases. No processing state is advertised as hardware-accepted.
6. Exact-source supply chain, dependency security, licence, rollback and user-approved installation acceptance. The working official Stremio 1.11.2 and account stay untouched.

**Install gate:** never install or distribute this MVP as a final Stremio client. It is a development candidate. Its source, tests and expected APK identity are preserved for independent review and later approved device tests.

### Persistent subtitle screen composition boundary

The disclosed mobile and Android TV subtitle labs now open state persistence,
same-installation receipt admission and the Android screen through one
owner-thread lifecycle authority. State and receipt `SharedPreferences` objects
must be distinct. Enabled state remains unadmitted unless the exact receipt
validator accepts the current complete preference snapshot, while explicit Off
does not manufacture or require a receipt. The Android screen is always closed
before the persistent state lease is released. This remains isolated lab
composition only: it is not private-client adoption, update migration, signed
delivery or device acceptance.

### App-private subtitle state migration boundary

The separate lab now models one installation-local schema update from its v1
mobile/TV state keys to distinct v2 keys. Migration occurs only while the exact
namespace lease is held. The legacy slot must be the sole present boolean; the
old slot is removed and the new slot is written through one synchronous editor
commit, followed by two matching exact reads. Explicit Off remains a present
false value and therefore cannot be mistaken for first run. A current/legacy
collision, non-boolean legacy value, refused or ambiguous commit, or concurrent
post-write drift closes the prospective owner and preserves unowned state.
Unrelated keys are never cleared.

This is a source-tested migration of the disclosed side-by-side lab only. It
does not establish the private Android clients' storage schema, an official
Stremio upgrade path, signed installation, update delivery or device
acceptance. Those gates remain open.

### Subtitle playback transition boundary

The playback actuator accepts only a stable complete player
snapshot and the exact installation-local preference admission. It cannot
replace a manual selection. Enabled can apply an automatic selection only with
the same-installation receipt; explicit Off or an unadmitted enabled value can
clear only a selection identified by the host as automatic. Episode transition
and recovery, plus a direct preference change, use the same one-shot lease,
final stable readback and player/video/source/load generation identity checks.

The disclosed TV lab now constructs the narrow Media3 adapter against its
generated local WAV and deterministic local English WebVTT sidecar. The
MediaItem therefore has an actual synthetic text track without reading a
network, provider, account or user subtitle file. The adapter changes only
whether the text track type is disabled, preserves all unrelated
track-selection parameters and stops when any manual text override exists.
An owner-thread observer accepts only the three fixed fixture cue strings for
the exact player/video/source/load generation, rejects unknown or oversized
input and cannot carry observations across a new load. The Activity reports
callback receipt separately from visible output. Hosted compilation and JVM
tests do not execute ExoPlayer playback, so they do not prove that any cue was
received or rendered. This remains source/build behaviour only, not visual
subtitle acceptance, private-client adoption, signed installation or Android
mobile/TV/Fire TV acceptance.

The Activity also converts Media3's text-only `Tracks` callback into a bounded
pure Kotlin observation. The exact local WebVTT MIME type, English language,
synthetic label and selected/unselected state must be the only reported text
track for the active player/video/source/load generation. Empty discovery is
recorded as absent; duplicate, unexpected or oversized text-track input closes
that generation. Runtime selection observation remains distinct from cue
receipt and visible rendering. Hosted CI compiles this binding and exercises
its deterministic contract but does not run Media3 playback or accept a
runtime track report.

The Activity also correlates the selected synthetic text track and monotonically
increasing deterministic cue callbacks within the same player/video/source/load
generation. Cues may arrive before the track callback without creating a false
selection claim. Absent or unselected tracks, malformed cue totals, regressing
cue counts, invalidated source observers, stale generations and foreign threads
fail closed. Even a selected track plus all three callbacks is labelled as
callback correlation only: it does not establish visible subtitle rendering.

The callback correlation is additionally bound to the exact installation-local
preference captured for that load. Admitted Enabled evidence requires stable
automatic-selection origin plus the selected track and all three deterministic
cue callbacks. A manual override can never be promoted as automatic preference
evidence. Enabled without the same-installation receipt remains held. Explicit
Off evidence requires the automatic selection to be cleared, the deterministic
track to remain unselected with zero expected cues and playback to reach its
natural synthetic end. Preference, context or playback-end regression closes
the generation. These are callback-only states: visible rendering remains
explicitly unaccepted, and hosted CI does not execute Media3 playback.

The TV lab now also attaches a bounded draw listener to Media3's own subtitle
view. For the same player, video, source and load generation, the observer
requires the exact preference-bound callback evidence, a newly reported cue
group, an attached, shown, fully opaque and non-zero-size subtitle view and a
draw callback for that exact cue revision. Admitted Enabled requires an active
validated cue. Explicit Off requires completed zero-cue callback evidence and
an empty draw. Missing receipt, manual selection, stale revisions, malformed
view state, identity drift and lifecycle or thread violations fail closed.

This is render-pipeline instrumentation only. A view draw does not establish
that subtitle pixels reached a display, were legible, survived composition or
were visible on a physical TV. `visibleRenderingAccepted`, pixel output and
device acceptance remain fixed false. Hosted CI compiles the Android binding
and exercises the pure observer, but does not run Media3 playback or observe a
real draw callback.

After that draw boundary, the TV lab may request one bounded `PixelCopy` of the
synthetic subtitle view rectangle for the exact cue revision. The bitmap is
never persisted: the callback reduces it to counts of opaque neutral-bright
pixels in the upper and lower bands, zeroes the temporary integer array, erases
the bitmap and recycles it. The pure observer accepts admitted Enabled only
when a small bounded signal is concentrated in the lower band and accepts
explicit Off only for an opaque nearly-dark frame. Stale identity, preference
or draw evidence, malformed dimensions, transparent pixels, unexpected bright
output, thread drift and lifecycle closure fail closed.

Each asynchronous copy is also owned by an immutable player/load/cue lease.
Only that exact current lease may resolve success or current failure. A newer
load supersedes an outstanding lease without allowing its late callback to
clear or invalidate the newer capture. Duplicate capture for the same cue,
older-load replacement, identity or revision drift, foreign-thread completion,
abandonment and lifecycle closure remain fail closed. This bounds callback
ordering only; it does not claim that hosted CI executed `PixelCopy`.

The API 30 instrumentation gate is intended to establish only that the exact
isolated Activity executed its local Media3 subtitle callbacks, draw path and
bounded `PixelCopy` reduction in a disposable Android emulator. It does not
show that a physical display presented legible text, that an official/private
client adopted the contract, that a signed build was installed, or that Android
TV, Fire TV or hardware acceptance passed. Emulator window-buffer evidence,
physical-panel evidence and device acceptance remain separate gates.
